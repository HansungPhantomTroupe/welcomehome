# welcomeHome API 명세 (웹 ↔ 서버)

웹이 부르는 엔드포인트와, 각 응답에 **어떤 데이터를 어떤 모양으로** 담아야 하는지 정리한 문서.
거르기·분류·순위 계산은 웹이 하므로, 서버는 아래 데이터를 이 모양 그대로 내려주면 된다.

## 0. 공통

**검사기**: 서버를 켠 뒤 `node tools/api-check.mjs http://서버주소:포트` (Node 18 이상, 설치할 것 없음). 아래 명세를 하나씩 확인해 틀린 엔드포인트·필드와 예시를 출력한다. 전부 맞으면 "모두 통과".

- 웹은 상대 경로 `/api/...` 로 부른다. 개발 중에는 웹 서버(Vite)가 `/api` 를 `http://localhost:4000` 으로 넘긴다 (`web/vite.config.ts` 의 `proxy.target` 에서 바꿈).
- 응답은 JSON (UTF-8).
- 실패하면 4xx/5xx 상태 코드와 `{ "error": "사용자에게 보여 줄 한국어 문장" }`. 웹은 `error` 문장을 그대로 화면에 띄운다.
- 필드 이름은 아래 표와 **대소문자까지 같게** (camelCase).

| 메서드 | 경로 | 언제 부르나 | 범위 |
|---|---|---|---|
| GET | `/api/bootstrap` | 앱을 열 때 1번 | 1차 |
| POST | `/api/custom/run` | AI가 만든 조건을 계산할 때 | 보류 (AI) |
| * | `/api/ai/*` | AI 탭 | 보류 (AI) |
| GET·POST·PUT·DELETE | `/api/personas` | 페르소나 관리 화면(`/personas`) · AI 가 참고 | 3장 |

## 1. GET `/api/bootstrap`

앱 전체가 쓰는 데이터를 한 번에. 요청 인자 없음.

| 키 | 내용 |
|---|---|
| `cells` | 지도 칸 전체 (지금 485개) — 1-1 |
| `dongStats` | 행정동 (지금 16개) — 1-2 |
| `meta` | 목적지 등 — 1-3 |

가게·시설 목록은 보내지 않는다. 웹이 시설 목록으로 하던 계산(가장 가까운 시설까지 거리, 가까운 지하철역 이름)은 서버가 해서 칸마다 `nearM`·`nearSubway` 로 붙인다.

- `slots[0][0]` 747.2 = `pop[0] + pop[1] + pop[2]` (167 + 208.7 + 371.5) — 월~목 08–12시의 거주 + 직장 + 방문
- `demo[0..11]` 합 = 1 — 월~목 · 거주 인구의 남(20대 미만~60대 이상) 6개 + 여 6개
- `poi.cafe` 6 > 0 이므로 `nearM.cafe` 61 ≤ 150 (칸 안에 있으면 칸 중심에서 꼭짓점까지 약 141m 이내)
- `nearSubway.m` 418 = `nearM.subway`

### 1-1. Cell (칸 하나, 200m × 200m)

필수 = 웹이 읽음. 선택 = 없어도 동작.

| 필드 | 타입 | 필수 | 내용 |
|---|---|---|---|
| `id` | string | 필수 | **`SB{i}_{j}` 형식 고정.** i·j 는 칸 격자의 행·열 번호(정수). 웹이 이 번호로 이웃 칸을 찾는다 (i+1 = 바로 옆 칸) |
| `center` | `{ lat, lng }` | 필수 | 칸 중심 (WGS84) |
| `corners` | `[{ lat, lng } × 4]` | 필수 | 칸 꼭짓점 4개, 둘레 순서 |
| `dongCode` | string | 필수 | 행정동 코드 (10자리). `dongStats[].code` 와 같은 값 |
| `dongName` | string | 필수 | 행정동 이름 |
| `slots` | `number[2][4]` | 필수 | 평균 인원. `[요일묶음][시간대]` |
| `pop` | `number[24]` | 필수 | 평균 인원을 인구 종류로 나눈 것. 아래 배치 |
| `demo` | `number[72]` | 필수 | 성별·연령 비율. 아래 배치 |
| `kindShare` | `{ resident, worker, visitor }` | 필수 | 하루 전체 인구 중 거주·직장·방문 비중 (0~1, 합 1) |
| `levels` | `{ total, wdEvening, wdNight, weNight }` | 필수 | 사람 수 단계 1~5 (1 매우 한적 ~ 5 혼잡). total 하루 전체, wdEvening 월~목 17–24시, wdNight 월~목 21–24시, weNight 금~일 21–24시 |
| `poi` | `{ food, cafe, conv, hosp, pharm, subway, mart, gym, bar }` | 필수 | 칸 안 시설 개수 (정수). `bar` = 음식점 중 술집 |
| `depts` | `string[]` | 필수 | 칸 안 병원의 진료과 이름 (중복 없이). 없으면 `[]` |
| `nearM` | `{ food, cafe, bar, conv, hosp, pharm, gym, subway, mart }` | 필수 | 칸 중심에서 종류별 **가장 가까운 시설까지 거리** (m, 정수). 그 종류가 하나도 없으면 `null`. `bar` = 술집 계열 음식점. "역 500m 안" 같은 거리 조건에 씀 |
| `nearSubway` | `{ name, m }` \| `null` | 필수 | 가장 가까운 지하철역 이름과 거리 (m). 400m 안이면 구역 이름을 "○○역 주변"으로 표시 |
| `popRaw` | `number[24]` | 선택 | `pop` 의 보정 전 원본 (같은 배치). 있으면 웹에서 원본 보기로 전환 가능 |
| `lguId` | string | 선택 | 원본 셀 번호 표시용 |
| `spike` | number | 선택 | 보정한 튀는 셀 수 (표시용) |
| `spread` | `{ apt, building, area }` | 선택 | 보정 방식별 수 (표시용) |
| `total` | number | 선택 | 하루 전체 평균 인원 (AI 스크립트용) |
| `cx`, `cy`, `type`, `tags`, `weekendSurge`, `nightShare`, `commuteMin` | | 안 씀 | 지금 웹이 읽지 않음. 빼도 됨 |

**인덱스 규칙** (모든 값은 2025년 월 평균, 그 시간대의 시간당 평균 인원):

| 축 | 값 |
|---|---|
| 요일묶음 d | `0` 월~목, `1` 금~일 |
| 시간대 t | `0` 08–12시, `1` 13–16시, `2` 17–20시, `3` 21–24시 |
| 인구 종류 k | `0` 거주, `1` 직장, `2` 방문 |
| 성별 s | `0` 남, `1` 여 |
| 연령 a | `0` 20대 미만, `1` 20대, `2` 30대, `3` 40대, `4` 50대, `5` 60대 이상 |

- `slots[d][t]` = 그 칸 전체 인원
- `pop[(d*4 + t)*3 + k]` = 인구 종류 k 의 인원. 같은 (d, t) 의 k 셋을 더하면 `slots[d][t]`
- `demo[((d*3 + k)*2 + s)*6 + a]` = 요일묶음 d · 인구 종류 k 인구 중 성별 s · 연령 a 의 비율. **같은 (d, k) 의 12개 합 = 1.** 시간대 구분 없음 (모든 시간대에 같은 비율 적용)

예시는 1장 맨 위 참고.

## 2. 보류 (AI)

AI 기능은 나중에 붙인다. 그때 필요한 것:

- `POST /api/custom/run` — AI가 만든 JavaScript 필터를 격리 실행기에서 모든 칸에 돌린다. 지금 Node 실행기(`server/src/customFilter.ts`)를 별도 서비스로 분리해 자바 서버가 호출하는 방식으로 할 예정.
- `/api/ai/status`, `/login`, `/login/finish`, `/logout`, `/models`, `/chat` — ChatGPT 로그인과 대화.

보류 중에는 웹의 AI 탭과 AI가 만든 조건만 동작하지 않고, 나머지는 1장만으로 모두 동작한다.

## 3. 페르소나 `/api/personas`

관리 화면(`/personas`)에서 "어떤 상황에서 어떤 조건을 왜 썼는지"를 저장하고, AI 가 다른 사용자에게 비슷한 목적의 사례로 알려 줄 때 참고한다. 접근 제한 없음.

Persona:
```jsonc
{
  "id": "pe387892140f0",
  "title": "저녁에 카페 작업하는 대학생 자취",          // 1~80자
  "description": "20대 대학생. 저녁에 활기찬 곳, 카페가 많은 곳…",   // 3000자 이하
  "stack": [FilterDef, …],          // 화면 조건 목록 그대로 (1~40개). 불러오기용
  "categories": [Category, …],      // 조건이 쓰는 동네 성격 정의 (다른 사람 화면에 없을 수 있어 함께 저장)
  "items": [{ "text": "카페 5곳 이상", "type": "poi", … }],   // AI 용: 화면 문장 + AI 항목 형식
  "createdAt": "ISO 시각",
  "updatedAt": "ISO 시각"
}
```

| 메서드 · 경로 | 요청 | 응답 |
|---|---|---|
| GET `/api/personas` | | `Persona[]` (최근 수정 순) |
| POST `/api/personas` | `{ title, description, stack, categories, items }` | 201 `Persona` |
| PUT `/api/personas/{id}` | POST 와 같음 | `Persona` · 없으면 404 |
| DELETE `/api/personas/{id}` | | `{ ok: true }` · 없으면 404 |

형식이 틀리면 400 `{ error }`. 저장소: PostgreSQL `wh_personas` 테이블 (DB 없으면 `data/personas.json`).
